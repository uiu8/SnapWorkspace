# 产品路线图

本路线图以 0.9.6 为当前基线，区分“已实现”“发布前必须完成”和“明确延期”。路线图不是当前功能承诺；当前行为以 [用户手册](USER_GUIDE.md) 和代码为准。

## 当前已实现

### 工作区基础

- 现代 .NET 10 WPF Fluent 桌面 UI；
- 工作区创建、编辑、删除、检查、恢复和部分恢复；
- 10 个完整原生 Snap Layout；
- 空槽位保留桌面；
- schema v5 统一保存原生、兼容和后台应用；
- schema v2–v4 自动迁移、覆盖前最多 20 份历史备份；
- `.snapworkspace` 全量备份/导入和单个 JSON 导入。

### 捕捉与编辑

- 智能捕捉和手动捕捉模式；
- 任务栏、托盘/驻留、纯后台三个范围自由组合，默认只启用任务栏；
- 手动点选任意顶层窗口；
- 捕捉角色建议、生成前检查和弱布局确认；
- 按路径/AUMID 的屏蔽、结构化通配规则和显式推荐系统规则；
- 记住应用角色并允许本次临时覆盖；
- 已安装应用目录、搜索、收藏和最近使用；
- 可视化拖动、拆分、合并和应用拖放，最终规范到原生模型。

### 恢复链路

- 已知 Shell 二进制、运行类和接口能力探测；
- 完整原生模型门、单次批量 `SnapWindows` 和 DWM 几何验证；
- EXE、AUMID、URI、参数、工作目录、提权和新实例启动；
- 路径、AUMID、类名、标题、通配符和正则窗口匹配；
- 后台前置事务、事件驱动隐藏、扫描兜底和子进程跟踪；
- Everything 原生后台协议；
- Chromium `--no-startup-window` 协议且不隐藏已有用户窗口；
- 非 Snap 窗口运行时路由到对应 Zone 的兼容定位；
- 冷启动兼容窗口与原生窗口的有限层级稳定；
- 旧异常兼容矩形自动修复；
- Windows 设置使用 `ms-settings:`；
- 可见窗口缺失时继续部分恢复。

### 日常使用与发布基础

- 原生通知区域图标、工作区快捷恢复和安全退出；
- 单实例激活；
- 登录启动的轻量托盘宿主，延迟构建完整主窗口；
- 搜索式命令面板；
- 主窗口、智能捕捉、新建工作区和三个快捷工作区的独立全局快捷键；
- 当前运行工作区状态、重新恢复和安全结束；
- 浅色、深色、系统主题、高对比度和键盘辅助；
- 7 天本地匿名诊断、隐私受控支持包；
- 框架依赖、自包含、可选 MSIX、SHA-256 和 GitHub Actions 发布链路。

## 首次公开 GitHub 发布前

### 兼容性矩阵

- 在一个稳定 Windows 11 和至少两个当前预览通道 build 上重新验证 Route 3；
- 记录 Shell DLL 版本、哈希、接口和最大窗口策略；
- 观察任务栏 Snap Group 卡片、共享分隔线、虚拟桌面和恢复后的拖动行为；
- 为不支持 build 给出明确的可操作说明，而不是只显示内部 HRESULT。

### 稳定性和回归

- 为代表性 Win32、UWP/MSIX、Electron、Chromium、固定窗口和启动器应用建立测试矩阵；
- 扩充真实后台协议样例和失败报告；
- 覆盖慢启动、多个同名窗口、启动器子进程、提权边界和系统重启后的数据迁移；
- 将手动点选、兼容矩形修复和 Chromium 前后台切换加入稳定 UI/集成回归；
- 对长期托盘驻留进行内存、句柄、钩子和计时器泄漏测试。

### 公开发布体验

- 使用可信证书签名正式安装包；
- 在干净机器验证安装、升级、卸载和数据保留；
- 完成 GitHub issue、PR、隐私和安全报告模板；
- 提供版本兼容表、截图和最小上手视频；
- 确认 self-contained 与 portable 包的版本、校验和、许可证和发布说明一致。

## 后续阶段

### 独立 Route 2 回退后端

设计一个明确标注的兼容后端，在 Route 3 不可用时提供普通工作区恢复，但不得：

- 把 `SetWindowPos` 结果称为 Snap Group；
- 对已经进入原生 Snap 的窗口追加几何校正；
- 弱化 Route 3 的已知二进制和完整模型门。

UI 应清楚显示当前工作区中哪些窗口走原生、哪些走兼容，以及失败时切换的后果。

### 应用适配配置

- 可扩展的应用专用后台协议；
- 启动器/子进程身份链规则；
- 导入导出可选的应用适配规则；
- 社区贡献前的安全审计与参数白名单；
- 更直观的逐应用准备时间线和可重试动作。

### 性能与驻留优化

- 测量轻量托盘宿主和完整 UI 的私有工作集、提交大小、冷/热启动和句柄数；
- 在不牺牲 Fluent UI、DPI、键盘和诊断能力的前提下延迟加载大型应用目录和捕捉清单；
- 主窗口隐藏后释放可安全重建的页面缓存；
- 建立发布版空闲 CPU 和内存回归阈值。

## 明确延期

多显示器功能暂不开发。当前 schema 保持单显示器语义，恢复目标是主工作区。恢复该功能前需要先完成：

- 显示器稳定身份与断开/重连映射；
- 不同 DPI、方向和任务栏工作区映射；
- 跨显示器工作区导入策略；
- 每个显示器独立 Snap 管理器与事务失败语义；
- 显示器缺失时的用户选择，而不是静默挤到主屏。

在这些问题没有统一设计前，不向 schema 添加看似兼容但无法保证的显示器字段。
