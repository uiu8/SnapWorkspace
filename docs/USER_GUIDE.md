# Snap Workspace 完整用户手册

本手册适用于 Snap Workspace 0.9.6。它从安装开始，说明如何创建、捕捉、编辑、恢复、结束、备份和排查工作区。

安装包见 [0.9.6 Release](https://github.com/uiu8/SnapWorkspace/releases/tag/v0.9.6)。推荐免装 .NET 的 `self-contained` ZIP；升级前先保存编辑并退出旧进程，避免单实例机制继续激活旧版。旧版安装包不具备本文新增的 0.9.6 兼容策略。

> 重要限制：当前原生 Snap 路径只支持通过能力探测的 Windows 11 Shell、主显示器和最多 4 个原生窗口。兼容定位及后台应用不计入 4 个原生窗口的上限。

## 安装并完成首次启动

发布包有两种：

| 包 | 是否自带 .NET | 适合谁 |
|---|---:|---|
| `win-x64-self-contained.zip` | 是 | 大多数用户，解压即可运行 |
| `win-x64-portable.zip` | 否 | 已安装 .NET 10 Desktop Runtime x64、希望下载更小包的用户 |

安装步骤：

1. 把压缩包解压到普通、可写的目录；
2. 运行 `SnapWorkspace.exe`；
3. 若 Windows 显示未知发布者提示，确认文件来自项目正式发布页后再运行；
4. 查看窗口左下角的 Route 3 状态。

状态含义：

- **路线三已启用**：当前 Shell 哈希位于已验证列表，且运行时接口探测通过；
- **路线三已启用 · 运行时兼容**：Shell 哈希未知，但运行类、`IsSupported`、manager 和必需接口均通过，可以提交原生 Snap；
- **兼容模式待接管**：原生路径未通过。包含原生窗口的工作区会在预检时停止，不会把普通位置调整冒充成 Snap Group；
- **正在检测 Shell**：应用仍在异步探测，稍后刷新或重新打开工作区。

软件是单实例应用。再次运行 `SnapWorkspace.exe` 会激活现有窗口，而不是再常驻一个完整进程。

## 创建工作区

### 从布局开始创建

1. 选择左侧“新建工作区”；
2. 在“选择 Snap Layout”中选布局；
3. 在每个应用槽位选择当前窗口，或使用“已安装应用”添加尚未运行的软件；
4. 不需要使用的槽位保持“留空，显示桌面”；
5. 根据需要展开“启动选项”和“窗口匹配规则”；
6. 添加兼容定位窗口或后台启动应用；
7. 填写名称，选择“仅保存”或“保存并恢复”。

“仅保存”不会移动或启动应用。“保存并恢复”先保存，再立即运行完整恢复流程。

### 给槽位添加未运行应用

选择“从已安装应用添加”或槽位旁的“已安装应用”。应用目录会综合读取：

- 开始菜单快捷方式；
- 传统已安装程序注册信息；
- AppsFolder 中的 UWP/MSIX 或带 AUMID 的桌面应用。

选择器支持搜索、收藏和最近使用。对于只有 AUMID 的桌面程序，恢复时会尝试解析实际可执行文件。

### 保留空槽位

空槽位是有意行为，不是布局损坏。以四宫格为例，只给左上和右下分配应用时：

- Windows 仍收到完整四宫格模型；
- 只提交两个已分配窗口；
- 另外两个区域没有窗口，继续显示桌面；
- 以后编辑时仍可向空槽位添加应用。

不要通过删除 Zone 来制造桌面空白。删除区域会使几何不再属于完整原生模型，预检将阻止原生提交。

## 捕捉现有桌面

### 智能捕捉

“智能捕捉”先建立当前应用清单，再建议每项角色。默认只开启“任务栏应用”，你可以自由组合以下范围：

| 范围 | 来源 | 默认状态 |
|---|---|---:|
| 任务栏应用 | 当前可见的普通顶层窗口 | 开 |
| 托盘 / 驻留应用 | Windows 通知区域注册与当前运行进程的交集 | 关 |
| 纯后台进程 | 没有任务栏窗口、也不属于托盘集合的可启动进程 | 关 |

三项可单独、两两或全部启用。相同启动目标会去重，优先级为任务栏、托盘、纯后台。

智能分类规则概括如下：

- 窗口样式、尺寸和当前可见区域适合 Snap，且原生集合未满 4 个：建议“原生吸附”；
- 有可见窗口但不适合原生 Snap，或原生集合已满：建议“兼容定位”；
- 启用范围内没有桌面窗口的进程：建议“后台启动”；
- 缺少稳定启动身份：建议“忽略”。

建议只是初始值。生成前可以把每项改为原生、兼容、后台或忽略；没有窗口的进程只能选择后台或忽略。

### 手动捕捉模式

“手动捕捉”使用相同清单，但桌面窗口默认忽略，启用范围内的无窗口进程默认后台。适合希望逐项明确决定、不接受自动布局建议的场景。

### 手动点选窗口

若某个程序标题为空、没有正常出现在清单中，或需要明确选中某个子窗口：

1. 在捕捉页选择“手动点选窗口”；
2. Snap Workspace 主窗口暂时隐藏；
3. 左键点击目标顶层窗口；
4. 按 `Esc` 或右键取消；
5. 返回清单后确认它的角色。

手动点选项的来源标为“手动选取”，不受任务栏、托盘、纯后台三个范围开关影响。固定对话框或不支持 Snap 样式的窗口会建议兼容定位。

### 屏蔽和记住角色

每个捕捉条目支持：

- **屏蔽**：以后不再出现在任何捕捉范围；
- **记住**：保存当前角色，下次自动预选相同角色；
- **临时修改**：本次改变角色，但不更新已保存规则。

屏蔽优先使用完整可执行路径，其次使用 AUMID，最后才使用显示名称。设置页还能添加路径、包族、发布者或名称通配规则。推荐系统屏蔽项不会自动启用，必须由用户确认添加。

## 选择正确的应用角色

### 使用原生吸附

适合普通、可调整大小、能响应 Windows Snap Layout 的窗口。恢复时这些窗口组成一个批次，传给 Windows Shell 的 `SnapWindows`。

原生角色要求：

- 绑定一个存在的 Zone；
- 一个 Zone 最多一个原生窗口；
- 全部原生窗口使用一个完整内置模型；
- 单次最多 4 个窗口；
- 当前窗口样式必须支持 Snap，否则运行时自动回退到对应 Zone 的兼容定位。

### 使用兼容定位

适合 EasyPub、固定尺寸工具、特殊渲染窗口或手工确认无法进入 Snap 的软件。它会：

- 在桌面显示；
- 保存相对主工作区的归一化位置；
- 恢复时定位一次；
- 不提交到 `SnapWindows`，因此不是 Snap Group 成员。

捕捉时优先读取窗口正常还原矩形，避免把最小化状态、越界状态或瞬时标题栏当成真实尺寸。异常小区域会被阻止；旧版本保存的极小区域可在首次成功恢复时根据当前窗口自动修复并回写。

### 使用后台启动

后台角色表示：恢复时应用应运行，但本次恢复事务内不能留下可见顶层窗口。它不占 Zone，也不会进入 Snap。

执行方式按应用不同而异：

- Chromium 系浏览器使用 `--no-startup-window`，不会强制隐藏已有用户窗口；
- Everything 使用 `-close` 后 `-startup` 的原生协议；
- 其他程序先使用隐藏启动提示，再监听新建/显示窗口并在事务内隐藏，同时追踪启动器的子进程；
- 后台阶段结束后立即释放隐藏规则，用户之后点击托盘图标应能正常显示窗口。

如果某个后台应用无法保持无窗口，桌面阶段会停止，避免突然出现的前台窗口与 Snap 提交竞争。详见 [故障排查](TROUBLESHOOTING.md)。

## 编辑布局与应用

### 使用内置布局

| Id | 中文名称 | Zone 数 |
|---|---|---:|
| `halves` | 左右二分 | 2 |
| `wide-left` | 左侧 2/3 + 右侧 1/3 | 2 |
| `wide-right` | 左侧 1/3 + 右侧 2/3 | 2 |
| `thirds` | 三列等分 | 3 |
| `main-left-stack` | 左侧主窗 + 右侧双栏 | 3 |
| `main-right-stack` | 右侧主窗 + 左侧双栏 | 3 |
| `half-left-stack` | 左半单栏 + 右半双栏 | 3 |
| `half-right-stack` | 右半单栏 + 左半双栏 | 3 |
| `center-focus` | 中间主窗 + 两侧窄栏 | 3 |
| `quarters` | 四宫格 | 4 |

### 使用可视化编辑器

可视化编辑器支持：

- 拖动共享分隔线；
- 左右或上下拆分当前 Zone；
- 合并所选相邻 Zone；
- 清空槽位中的应用；
- 把应用拖到其他 Zone；
- 恢复初始布局。

编辑器的目标不是制造任意矩形，而是寻找最近的受支持原生模型。“应用原生模型”后，几何会吸附到内置比例。未分配槽位继续存在并显示桌面。

如果编辑结果无法精确对应已验证模型，包含原生角色的工作区无法通过预检。此时应恢复为原生模型，或把相应窗口改为兼容定位。

### 设置窗口匹配规则

恢复不能保存 HWND，因为 HWND 只在当前会话有效。应用通过路径/AUMID、窗口类和标题重新匹配。

进程识别：

- 自动判断；
- 完整路径 / AUMID；
- 仅文件名；
- 忽略进程。

标题识别：

- 自动判断；
- 标题完全相同；
- 标题包含文字；
- 通配符 `*` / `?`；
- 正则表达式；
- 忽略标题。

还可要求窗口类完全相同。不能同时忽略进程、标题和窗口类，否则没有任何可验证身份。正则匹配有 100 毫秒超时，避免复杂表达式阻塞恢复。

建议：浏览器、编辑器等标题经常变化的应用用“完整路径 + 标题包含”；多实例应用再加窗口类或更明确标题规则。

### 设置启动选项

每个应用可配置：

- 可执行文件或 AUMID；
- 启动 URI（系统表面内部使用，例如 `ms-settings:`）；
- 启动参数；
- 工作目录；
- 以管理员身份运行；
- 始终启动新实例。

默认优先复用匹配的现有窗口。“始终启动新实例”会要求恢复后出现新的 HWND，适合明确需要独立窗口的程序，但不适合强制单实例应用。

## 恢复工作区

可从以下入口恢复：

- 工作区库中的“恢复”；
- 当前运行横幅中的“重新恢复”；
- 通知区域图标的工作区菜单；
- 命令面板；
- 三个快捷工作区全局热键。

恢复过程：

1. 预检工作区结构、Shell 能力、路径和候选窗口；
2. 解析并启动后台应用，确认没有可见窗口；
3. 复用或启动可见应用，最多等待 15 秒匹配窗口；
4. 把不支持 Snap 的原生候选路由到兼容定位；
5. 一次性向 Shell 提交剩余原生窗口；
6. 等待 250–1500 毫秒后，用 DWM 可见边界验证位置；
7. 定位兼容窗口，并在冷启动时短暂稳定与原生窗口重叠的层级；
8. 记录当前运行会话并释放后台隐藏规则。

某个可见应用缺失时，只要还有其他可见窗口准备成功，恢复会继续，缺失 Zone 保持桌面可见。后台应用失败则会停止桌面阶段，因为后台是前置保证而不是可忽略的副作用。

## 结束工作区

“结束工作区”结束的是 Snap Workspace 的当前会话管理，不会无条件杀进程。

你可以：

- 保持所有应用原状；
- 向本次恢复新启动、当前仍有效的可见窗口发送普通 `WM_CLOSE` 请求。

普通关闭允许应用弹出“是否保存”。恢复前已存在的窗口、后台进程和无法确认所有权的窗口不会被强制关闭。

当前会话是进程内状态。退出 Snap Workspace 后再次打开，软件不会根据桌面位置猜测哪个窗口属于之前的工作区。

## 使用托盘、启动项和快捷命令

设置页可控制：

- 启用通知区域图标；
- 关闭主窗口时进入托盘；
- 登录 Windows 后启动；
- 从启动项运行时直接进入轻量托盘宿主；
- 启用全局快捷键。

登录启动只注册当前用户 Run 项，不请求管理员权限，也不会自动恢复某个工作区。启用“直接进入托盘”时，完整 WPF 主窗口会延迟到真正需要显示或恢复时才构建。

默认快捷键模板：

| 动作 | 默认组合 | 默认启用 |
|---|---|---:|
| 命令面板 | `Ctrl+Alt+Space` | 是 |
| 显示主窗口 | `Ctrl+Alt+W` | 否 |
| 智能捕捉 | `Ctrl+Alt+C` | 否 |
| 新建工作区 | `Ctrl+Alt+N` | 否 |
| 快捷工作区 1 | `Ctrl+Alt+1` | 是 |
| 快捷工作区 2 | `Ctrl+Alt+2` | 是 |
| 快捷工作区 3 | `Ctrl+Alt+3` | 是 |

快捷工作区还必须分配目标工作区才会注册。选择快捷键输入框后直接按组合键，`Delete` 清空；组合键至少包含 `Ctrl`、`Alt`、`Shift` 或 `Win` 之一。重复组合、格式错误或已被其他软件占用都会显示注册失败原因。

主窗口局部快捷键：

| 快捷键 | 动作 |
|---|---|
| `Ctrl+N` | 新建工作区 |
| `Ctrl+Shift+C` | 捕捉工作区 |
| `Ctrl+S` | 保存当前编辑 |
| `F5` | 刷新窗口清单 |
| `Ctrl+,` | 打开设置 |
| `Esc` | 返回工作区库 |

命令面板使用 `↑` / `↓` 选择、`Enter` 执行、`Esc` 关闭。已分配的三个快捷工作区会固定在结果顶部。

## 备份、导入和升级

### 备份全部工作区

在工作区库选择“备份”，保存为 `.snapworkspace`。它是 ZIP 容器，包含清单和所有规范化工作区 JSON，不包含设置、诊断日志或应用程序本体。

### 导入工作区

“导入”接受：

- `.snapworkspace`：一次导入包内全部工作区；
- `.json`：导入单个工作区定义。

如果 Id 与现有工作区相同，现有文件不会被覆盖；导入项会获得新 Id，名称追加“（导入）”。

### 升级软件

1. 从托盘菜单彻底退出 Snap Workspace；
2. 解压新版本到新目录或替换程序文件；
3. 启动新版本；
4. 检查 Route 3 能力状态；
5. 先用不重要的工作区测试恢复。

工作区和设置位于 `%LOCALAPPDATA%\SnapWorkspace`，不在程序目录，升级压缩包不会自动删除它们。旧 schema v2–v4 会在读取时迁移，下一次保存写为 schema v5。

## 数据位置与无障碍

本地数据根目录：`%LOCALAPPDATA%\SnapWorkspace`。详细结构见 [工作区数据格式](WORKSPACE_FORMAT.md)。

界面支持浅色、深色和跟随系统；检测到 Windows 高对比度时改用系统颜色。主要操作有自动化名称，可通过 `Tab`、方向键和键盘快捷键访问。
