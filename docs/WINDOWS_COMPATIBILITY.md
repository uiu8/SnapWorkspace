# Windows 版本建议与兼容边界

核查日期：2026-10-03。适用于当前 x64、Route 3 / v3 原生 Snap 后端。

**日常系统选型建议：Windows 11 25H2 x64 正式版，并安装最新累积更新。已确认的早期接口门槛则是 22H2 / 23H2 的 2024-01-23 更新 `.3085`。两者不是同一个概念。**

这里的“理论运行能力”只表示系统具备重要的接口基础，不代表已经在该版本完成整机兼容认证。无需为了使用 Snap Workspace 安装 Insider 预览版。

## 建议版本与发布时间

| Windows 11 版本 | 正式发布时间 | 原生后端的理论接口基础 | 使用建议 |
|---|---|---|---|
| 22H2 | 2022-09-20 | 从 `22621.3085` 样本确认 v3，需安装 2024-01-23 的 KB5034204 或后续累积更新 | 仅作为历史兼容下限，不建议新装 |
| 23H2 | 2023-10-31 | 对应 `22631.3085` 更新；22H2 / 23H2 共用的 Shell 文件版本为 `22621.3085` | 已有环境可测试，不建议新装 |
| 24H2 | 2024-10-01（普遍发布） | 初始基线 `26100.1` 已通过 DLL / PDB 静态核查，包含 v3 | 有明确接口基础；新装优先选择维护期更长的版本 |
| 25H2 | 2025-09-30 | 微软说明与 24H2 共用核心及系统文件；据此推定具备基础，仍需自检 | 日常使用建议选择，并保持更新 |

发布时间依据：[22H2 发布公告](https://blogs.windows.com/windowsexperience/2022/09/20/how-to-get-the-windows-11-2022-update/)、[微软版本信息](https://learn.microsoft.com/en-us/windows/release-health/windows11-release-information)。24H2 的日期按普遍发布口径，不把此前部分新设备的预装时间混入表中。

23H2 和 25H2 的共用系统文件关系分别见 [KB5027397](https://support.microsoft.com/help/5027397) 和 [KB5054156](https://support.microsoft.com/help/5054156)。25H2 的选型建议不是本项目已经在其所有补丁版本完成行为测试的声明；其他更新分支也不能仅凭版本号更高就视为通过。

## 最早确认的更新门槛

本项目对微软原始 x64 Shell 文件及匹配的公开 PDB 进行静态核查，确认下列相邻公开更新的差异：

| 系统更新 | 发布日期 | OS build | 样本核查结果 |
|---|---|---|---|
| [KB5034123](https://support.microsoft.com/help/5034123) | 2024-01-09 | `22621.3007` / `22631.3007` | Shell 的实现接口集合仍为 v1/v2，没有 v3 IID 或实现符号 |
| [KB5034204](https://support.microsoft.com/help/5034204) | 2024-01-23 | `22621.3085` / `22631.3085` | 出现 v3 IID、v1/v2/v3 接口集合，以及 `ISnapLayoutManager3::SnapWindows` 实现 |
| [KB5034765](https://support.microsoft.com/help/5034765) | 2024-02-13 | `22621.3155` / `22631.3155` | 后续安全累积更新，同样包含 v3 实现 |

关键 `.3007`、`.3085`、`.3155` 样本的 SHA-256 均与历史索引相符；证据、微软下载地址和 PDB 片段见 [接口样本记录](evidence/snap-interface-history-2026-10-03.json)。不是只搜索了几个可打印的接口名称。

准确结论是：**2024-01-23 的 `.3085` 是本次确认的公开维护分支引入边界及最早样本**。没有穷尽所有 Insider、内部构建及 CPU 架构，不能将其宣称为微软内部绝对首次实现的版本。也没有逐个验证每一个后续补丁。

上述微软 KB 说明用于证明日期与版本，并未公开宣告这个私有接口；接口存在性的结论来自本项目的 DLL / PDB 分析，不是微软提供的受支持 API 合同。

## 系统有接口，为什么软件仍可能拒绝？

需要同时区分系统版本、Snap Workspace 版本和实际桌面环境：

| 检查层 | 要求 | 不能据此推导的结论 |
|---|---|---|
| 应用本身 | Windows x64；框架依赖包还需 .NET 10 Desktop Runtime | 安装 .NET 不会给系统增加缺失的 Snap 接口 |
| Shell 激活 | 能取得运行类工厂，`IsSupported` 调用成功且为 true | DLL 文件存在不等于工厂可用 |
| 管理器接口 | 工作区管理器创建成功，Manager2 / Manager3 查询成功 | 有 v3 的符号不等于当前进程能调用 |
| 实际恢复 | 合法模型、有效窗口、正确坐标，提交和结果验证通过 | HRESULT 成功或几何到位不等于所有 Snap Group 交互均已验证 |

v4 不是当前批量恢复的必需项。当前最多提交 4 个原生窗口是产品的配置和验证边界，不是对 Windows 全部布局能力的断言。

### 0.9.5 与 0.9.6 的区别

- 0.9.5 及更早版本默认还要求 Shell 二进制命中已验证哈希。因此即使系统已有 v3，也可能被旧版应用拒绝。
- 0.9.6 的实现不再将精确哈希作为硬门槛，改由运行时接口探测决定是否启用；哈希继续用于诊断和兼容等级。
- 新旧版本都不能用“跳过失败检测”的方式获得系统中不存在的接口。

请先确认**实际运行进程**的版本，而不只是下载文件夹的名称。单实例程序可能把新启动请求转交给仍在运行的旧版进程。源码、安装包和 Release 页面也可能处于不同版本，不能只看其中一个。

## 给用户的简短结论

> 推荐 Windows 11 25H2 x64 正式版并保持更新。原生 v3 的早期接口基础已确认到 22H2 / 23H2 的 `.3085` 更新及 24H2 初始基线，但最终以软件能力检测和实际恢复验证为准。不承诺所有 Windows 11 或所有第三方窗口都能原生吸附。

这是历史兼容依据，不是建议回装过时系统或补丁。当前 HWND → WindowId 转换仍有跨版本适配事项，详见 [原生 Snap 调用原理](NATIVE_SNAP_INTERNALS.md)。
